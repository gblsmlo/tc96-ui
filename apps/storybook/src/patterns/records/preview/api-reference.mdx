# Record Preview

A modal sheet on the right that previews one record without leaving the screen: a task opened from a board card, a contact opened from a table row, a version opened from a list. Reach for it when the user wants the details of a record at a glance and still has the collection behind it. The consumer owns the open state, the content, the trigger, the URL and the record lookup; the preview shows the error and not found states of that lookup from `status`, `RecordPreviewFrame` shows its loading as a loading `RecordGroup`, and the preview never fetches, confirms or keeps a record.

The other pages of `Patterns/Records/Preview`: [Playground](?path=/story/patterns-records-preview-playground--playground) to try the texts, the header actions, the footer and the content, [Variants](?path=/story/patterns-records-preview-variants--default) for the default sheet and the error and not found states, [Behavior](?path=/story/patterns-records-preview-behavior--named-by-title-with-one-close-button) for the tests, and [Layouts](?path=/story/patterns-records-preview-layouts--title-only) for how the header, the body column and the footer combine. Previews with real content are the blocks under `Blocks/Application/Record Preview`: [RecordPreview1](?path=/story/blocks-application-record-preview-recordpreview1--record-preview-1) and [RecordPreview2](?path=/story/blocks-application-record-preview-recordpreview2--record-preview-2) for a task (badge and plain properties), [RecordPreview3](?path=/story/blocks-application-record-preview-recordpreview3--record-preview-3) for a row of the task collection and [RecordPreview4](?path=/story/blocks-application-record-preview-recordpreview4--record-preview-4) for a lawsuit and [RecordPreview5](?path=/story/blocks-application-record-preview-recordpreview5--record-preview-5) for a row of the documents collection, [RecordPreview6](?path=/story/blocks-application-record-preview-recordpreview6--record-preview-6) for a finance entry, [RecordPreview7](?path=/story/blocks-application-record-preview-recordpreview7--record-preview-7) for a legal matter, [RecordPreview8](?path=/story/blocks-application-record-preview-recordpreview8--record-preview-8) for a deadline with its decision buttons, [RecordPreview9](?path=/story/blocks-application-record-preview-recordpreview9--record-preview-9) for a court publication with its decisions and full text, [RecordPreview10](?path=/story/blocks-application-record-preview-recordpreview10--record-preview-10) for a capture failure and [RecordPreview11](?path=/story/blocks-application-record-preview-recordpreview11--record-preview-11) for a capture run.

Used in: the block [RecordGroup4](?path=/story/blocks-application-record-group-recordgroup4--record-group-4) opens a form in a `RecordPreview` from a row, with the save state in the description and the commands in the footer, and [RecordGroup5](?path=/story/blocks-application-record-group-recordgroup5--record-group-5) opens each version read-only. The block [RecordPreview1](?path=/story/blocks-application-record-preview-recordpreview1--record-preview-1) puts collapsible `RecordGroup` sections of `properties` values inside the body, with the read-only ones `plain`.

## Import

```tsx
import {
  RecordPreview,
  RecordPreviewBody,
  RecordPreviewCover,
  RecordPreviewDecisions,
  RecordPreviewFrame,
  RecordPreviewRegister,
} from '@acme/patterns'
```

`RecordPreview` is the bare sheet. A preview with a record behind it is usually assembled from the parts below: `RecordPreviewFrame` in place of `RecordPreview`, and `RecordPreviewCover`, `RecordPreviewRegister` and `RecordPreviewDecisions` inside `RecordPreviewBody`. The eleven blocks under `Blocks/Application/Record Preview` differ only by which parts they compose and by their own rows.

## Anatomy

`RecordPreview` with the three header actions and `RecordPreviewBody` as its content:

```tsx
<div data-slot="sheet-backdrop" />

    <div data-slot="sheet-header">
      <h2 data-slot="sheet-title">{title}</h2>

      <div data-slot="record-preview-header-actions">
        <button aria-label={more.label} aria-haspopup="menu" />
        <button aria-label={expand.label} />
      </div>
      <button data-slot="sheet-close" aria-label={closeLabel} />
    </div>
    <div data-slot="scroll-area-viewport">

    </div>
    <div data-slot="sheet-footer">{footer}</div>
  </div>
</div>
```

Plain `div` wrappers with no `data-slot` group the title and the description, and the actions and the close button, inside the header.

## RecordPreview

A modal sheet that holds the preview of one record. Renders a `div` with `role="dialog"` in a portal on `body`, named by `title`, over a backdrop, with a header, a scrolling panel for `children` and an optional footer. It is controlled: it opens and closes only through `open`, and asks to close through `onOpenChange(false)` on `Escape`, a press outside and the close button. It has no content of its own and keeps no state besides a reference to its popup.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `open` | `boolean` | required | Controls whether the preview is open. |
| `onOpenChange` | `(open: boolean) => void` | required | Called with `false` when the preview asks to close, on `Escape`, a press outside and the close button. |
| `title` | `ReactNode` | required | Sets the title, which names the dialog. |
| `closeLabel` | `string` | required | Sets the accessible name of the close button; there is no default. |
| `description` | `ReactNode` | - | Sets the text under the title, which describes the dialog. |
| `more` | `RecordPreviewMore` | - | Renders the more button, which opens a menu of `actions` and calls `onAction` with the `id` of the chosen one; without actions no more button renders. |
| `expand` | `RecordPreviewExpand` | - | Renders the open button, named by `label`, which calls `onClick`; without it no open button renders. |
| `children` | `ReactNode` | - | Sets the content of the scrolling panel, such as `RecordPreviewBody`. |
| `footer` | `ReactNode` | - | Renders a footer below the panel, outside the scroll; without it no footer renders. |
| `finalFocus` | `() => HTMLElement \| null` | - | Called when the preview closes to pick the element that receives focus; `null` keeps the default. |
| `className` | `string` | - | Adds classes to the popup. |
| `status` | `'ready' \| 'error' \| 'not-found'` | `'ready'` | Sets the state of the record lookup. While it is not `'ready'` the body shows the state instead of `children`, and `more`, `expand` and `footer` do not render. |
| `statusLabels` | `RecordPreviewStatusLabels` without `loading` | required when `status` is not `'ready'` | Sets the copy of the states; the types refuse a `status` other than `'ready'` without it, and the preview has no default copy. |
| `onRetry` | `() => void` | - | Called when the retry button of the `error` state is clicked; the button renders only when it is passed. |

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"sheet-popup"` | Selects the popup, which takes `className` |
| `data-open`, `data-closed` | present while open, or while closed and animating out | Style the popup by state |
| `data-starting-style`, `data-ending-style` | present while the popup animates in, or out | Style the 200ms fade and the 32px slide |
| `data-slot` | `"sheet-backdrop"` | Selects the layer that dims the page |
| `data-slot` | `"sheet-viewport"` | Selects the fixed layer around the popup; a press on it, outside the popup, asks to close |
| `data-slot` | `"sheet-header"` | Selects the header |
| `data-slot` | `"sheet-title"` | Selects the title |
| `data-slot` | `"sheet-description"` | Selects the description; it renders only with `description` |
| `data-slot` | `"record-preview-header-actions"` | Selects the wrapper of the more and open buttons; it renders only when one of them does |
| `data-slot` | `"sheet-close"` | Selects the close button |
| `data-slot` | `"sheet-panel"` | Selects the panel that holds `children` |
| `data-slot` | `"sheet-footer"` | Selects the footer; it renders only with `footer` |

### Header

The title is an `h2` in `text-base leading-snug`. It wraps beside the actions, which stay at the top end, and is never truncated. `description` sits under it in `muted-foreground`.

### Actions

The header has three actions, in this order, as ghost icon buttons in a row with a 2px gap: more (three dots), open (arrows out) and close (an X). The pattern draws the icons; the consumer passes only the labels and the callbacks. More opens a menu aligned to the end with one item per entry of `more.actions` and calls `more.onAction` with the `id` of the chosen one; an entry with `disabled` stays in the menu and does nothing. Open shows its `label` in a tooltip on hover and on keyboard focus and calls `expand.onClick`. Close is always rendered, named by `closeLabel`, which has no default, and is the only close button the popup has; it calls `onOpenChange(false)`.

| `RecordPreviewMoreAction` key | Type | Description |
| --- | --- | --- |
| `id` | `string` | Identifies the action in the call to `onAction`. |
| `label` | `string` | Sets the text of the menu item. |
| `disabled` | `boolean` | When true, the item renders disabled and is not called. |

### Panel and footer

The panel scrolls inside a scroll area, with 16px of padding and a fade at the edges while the content overflows; the header and the footer stay in place. The footer renders only with `footer`, below the panel and outside the scroll, with a top border, a `muted` background at 72% opacity and 16px of inline padding. From `sm` up its buttons sit in a row at the end; below `sm` they stack, the first at the bottom. The preview never confirms a destructive action: the footer buttons and any confirmation are the consumer's.

### Status

Loading is not a state of the sheet: the groups of the body show it, through the `loading` of `RecordGroup` (`Patterns/Records/Group`), and `RecordPreviewFrame` does it for a lookup. With `status="error"` it renders the `StateSurface` of `Patterns/Surfaces/State` with kind `error` (role `alert`), `errorTitle` and `errorDescription`, and a button labelled `retry` that calls `onRetry`, only when `onRetry` is passed. With `status="not-found"` it renders the same surface with kind `not-found`, `notFoundTitle` and `notFoundDescription`. The title, the description and the close button stay; the more and open buttons and `footer` are hidden, so nothing acts on a record that is not there.

| `RecordPreviewStatusLabels` key | Type | Description |
| --- | --- | --- |
| `loading` | `string` | The accessible name of the loading group; read by `RecordPreviewFrame`, not by `RecordPreview`. |
| `errorTitle` | `string` | The title of the error state. |
| `errorDescription` | `string` | Optional text under the error title. |
| `notFoundTitle` | `string` | The title of the not found state. |
| `notFoundDescription` | `string` | Optional text under the not found title. |
| `retry` | `string` | The label of the retry button. |

### Placement

The sheet opens from the right edge. Its popup is 448px wide at most and `calc(100% - 48px)` below that. From `sm` up it floats 16px from the viewport edges with rounded corners and a border. There is no size prop; `className` goes to the popup.

### Focus

The sheet is modal: the backdrop dims the page and focus stays inside until it closes. Focus goes to the popup itself (`tabindex="-1"`), not to the first control, so a preview opened from the keyboard still answers to `Escape`. Closing returns focus to the element that was focused on open.

When that element is gone by then, as with a card that moved to another column, `finalFocus` is read at close time and returns the element to focus instead. Returning `null` keeps the default. A Kanban below `md` renders only the active column, so the moved card may not be in the DOM: fall back to the column option of the collection, `[data-kanban-column-option="<column id>"]`, after the visible `[data-record-id]` card.

## RecordPreviewFrame

The sheet for a preview whose content comes from a lookup that may not have a record yet. Renders a `RecordPreview` and owns the rules every record preview repeats: the title falls back to `fallbackTitle` while there is no title, a `hasRecord` of `false` with a `status` of `'ready'` is shown as `'not-found'`, and a `status` of `'loading'` renders the sheet with a loading `RecordGroup` in the body, named by `statusLabels.loading`, in place of `children`. Layouts: [Frame](?path=/story/patterns-records-preview-layouts--frame). The `RecordPreview` props not listed below (`open`, `onOpenChange`, `closeLabel`, `description`, `more`, `expand`, `footer`, `finalFocus`, `className`, `onRetry`, `children`) pass through unchanged.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `ReactNode` | - | Sets the title; when it is `undefined` or `null`, `fallbackTitle` is used. |
| `fallbackTitle` | `ReactNode` | - | Sets the title while `title` is empty, such as before the record loads. |
| `hasRecord` | `boolean` | `true` | Tells the frame whether the lookup returned a record. While it is `false` and `status` is `'ready'`, the preview shows the not found state. |
| `status` | `'ready' \| 'loading' \| 'error' \| 'not-found'` | `'ready'` | Sets the state of the lookup: `'loading'` as above, the others as in `RecordPreview`. |
| `statusLabels` | `RecordPreviewStatusLabels` | required when `status` or `hasRecord` is passed | Sets the copy of the states, which the frame has no default for. Without both props the frame is always ready and needs none. |
While loading, the more and open buttons and `footer` are hidden, as in the other states.

## RecordPreviewCover

The tile at the top of the body: the picture of a record, or a stand-in for it. Renders a `div` with `data-slot="record-preview-cover"` and rounded corners on a `muted` background. With `src` it holds an `img` in a 16:9 box; without it, `fallback` centered in a 112px box. Layouts: [Cover](?path=/story/patterns-records-preview-layouts--cover).

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `src` | `string \| null` | - | Sets the picture; empty renders `fallback` instead. |
| `alt` | `string` | required | Sets the text alternative of the picture. |
| `fallback` | `ReactNode` | required | Renders the stand-in when there is no `src`, such as an `IconFrame`. |
| `className` | `string` | - | Adds classes after the base classes. |

It also takes the other attributes of a `div`, such as `data-slot`, which replaces the default.

## RecordPreviewRegister

The group that every record ends with: its identifier, when it was created and changed, and who made it. Renders a `RecordGroup` of read-only rows in the `plain` variant: the ID with a copy button, the two timestamps as a `DateProperty` with the value icon hidden, and the author as a `PersonProperty`. A row renders only when its prop is passed. Layouts: [Register](?path=/story/patterns-records-preview-layouts--register).

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `ReactNode` | required | Sets the title of the group. |
| `id` | `{ label: string; value: string }` | required | Sets the label and the value of the ID row. |
| `copyLabel` | `string` | required | Sets the accessible name of the button that copies the ID. |
| `createdAt` | `{ label: string; value: string }` | - | Renders the created row; `value` is an ISO instant. |
| `updatedAt` | `{ label: string; value: string }` | - | Renders the updated row; `value` is an ISO instant. |
| `author` | `{ label: string; options: PersonPropertyOption[]; placeholder: string; value: string \| null }` | - | Renders the author row, naming the option whose `value` matches. |
| `locale` | `string` | required | Sets the locale of the timestamps. |
| `timeZone` | `string` | - | Sets the time zone of the timestamps; the default is the browser's. |
| `defaultOpen` | `boolean` | `true` | When false, the group starts collapsed. |

## RecordPreviewDecisions

The row of buttons that decide on the record, such as confirm and reject. Renders a `fieldset` with `data-slot="record-preview-decisions"`, named by `label`, as a flex row with an 8px gap. Place it in the `footer` of the preview, so the decisions stay in view below the scrolling panel. The buttons are the consumer's and so is when to render the group. Layouts: [Decisions](?path=/story/patterns-records-preview-layouts--decisions).

| Prop | Type | Default | Description |
| --- | --- | --- | --- |

| `children` | `ReactNode` | - | Sets the buttons. |
| `className` | `string` | - | Adds classes after the base classes, such as `flex-wrap`. |

It also takes the other attributes of a `fieldset`, such as `data-slot`, which replaces the default.

## Accessibility and theme

- Every label is the consumer's: pass `title`, `closeLabel`, `more.label`, `expand.label` and the `label` of each more action. None has a default.
- The header icons are the pattern's and are hidden from assistive technology; each button is named by its label.
- The content is the consumer's, so its controls and headings are too; the loading, error and not found copy is passed in `statusLabels`.
- The preview uses the `popover`, `popover-foreground`, `muted`, `muted-foreground`, `foreground` and `ring` tokens. Measured contrast: `docs/accessibility.md`, section `record-preview`.
